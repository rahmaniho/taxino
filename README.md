# TAXINO — صفحهٔ فرود محصول «مدیریت هوشمند آژانس تاکسی»

صفحهٔ فرود فارسی و راست‌به‌چپ برای محصول **TAXINO** (نرم‌افزار مدیریت آژانس تاکسی تلفنی، نسخهٔ ۱.۶.۰) از شرکت **کارن‌سافت**.
پیام اصلی: «مدیریت هوشمند آژانس تاکسی، از یک نقطه.» — مخاطب: مدیر آژانس تاکسی تلفنی و دیسپچ، نه مسافر.

- پشتهٔ فناوری: **Vite 7 + React 19 + TypeScript 5.9 + Tailwind CSS 4 + GSAP/ScrollTrigger**
- فونت: Vazirmatn (فارسی) + Inter (لاتین) — هر دو self-host شده و زیرمجموعه‌سازی‌شده (بدون CDN)
- بک‌اند واقعی فرم مشاوره: تابع بدون وابستگی روی Node (`/api/consult`)

---

## ۱) اجرای پروژه

```bash
npm install          # نصب وابستگی‌ها
npm run assets       # تولید تصاویر بهینه و فونت‌ها در public/assets (لازم است یک بار اجرا شود)
npm run dev          # اجرای محلی روی http://localhost:5173
```

ساخت نسخهٔ تولید و اجرای آن:

```bash
npm run build        # typecheck + build → dist/
npm start            # سرور تولید (استاتیک + /api/consult) روی http://localhost:4173
```

اجرای کل دروازهٔ کیفیت:

```bash
npm run qa           # tsc → build → SSR snapshot → audit → api tests
npm run qa:audit     # فقط ممیزی ساختاری/SEO/axe
npm run qa:api       # فقط تست‌های قرارداد API فرم
```

**متغیرهای محیطی** (نمونه در `.env.example`):

| متغیر | کاربرد | پیش‌فرض |
| --- | --- | --- |
| `LEAD_DIR` | مسیر ذخیرهٔ سرنخ‌ها (JSONL با دسترسی 0600) | `./var/leads` |
| `LEAD_WEBHOOK_URL` | ارسال هر سرنخ به وبهوک/CRM | خالی |
| `PORT` / `HOST` | سرور تولید | `4173` / `0.0.0.0` |
| `VITE_BASE` | مسیری که سایت در آن سرو می‌شود | `/` (`/taxino/` روی گیت‌هاب پیجز) |
| `PUBLIC_SITE_URL` | مبدأ مطلق برای canonical/OG/JSON-LD | `https://www.taxino.ir` |
| `VITE_CONSULT_ENDPOINT` | نشانی API فرم در صورت میزبانی جدا | `/api/consult` |

## ۵) فرم مشاوره — قرارداد API

`POST /api/consult` با بدنهٔ JSON:

```json
{ "name": "…", "phone": "۰۹۱۲…", "agency": "…", "city": "…",
  "drivers": 12, "note": "…", "plan": "یک‌ساله", "consent": true,
  "source": "landing", "website": "" }
```

| پاسخ | معنا |
| --- | --- |
| `200 {ok:true,id:"TX-…"}` | سرنخ پذیرفته و **ذخیره** شد |
| `400 {ok:false,errors:{…}}` | خطای اعتبارسنجی میدانی (پیام فارسی برای هر فیلد) |
| `415` | Content-Type غیر JSON |
| `413` | بدنهٔ بزرگ‌تر از ۸ کیلوبایت (اتصال بسته می‌شود) |
| `429` | بیش از ۵ درخواست از یک IP در ۱۰ دقیقه |
| `503` | هیچ مقصد ذخیره‌سازی در دسترس نیست (فرم موفقیت جعلی نشان نمی‌دهد) |

تدابیر امنیتی: honeypot (`website`)، الزام `consent`، نرمال‌سازی شمارهٔ موبایل ایران، محدودسازی طول همهٔ فیلدها، هدرهای `no-store` و `X-Content-Type-Options`، ذخیره‌سازی `0600` و قفل هم‌زمانی روی فایل سرنخ‌ها.

### آنچه اندازه‌گیری **نشده** است (صادقانه)

- **Lighthouse / Lighthouse CI**: در این محیط هیچ مرورگری (Chrome/Chromium) نصب نیست و دانلود باینری Playwright شکست می‌خورد؛ بنابراین امتیاز Lighthouse **تولید و ادعا نشده** است. برای اندازه‌گیری روی ماشین دارای Chrome: `npx lighthouse http://localhost:4173 --preset=desktop --view`.
- **اسکرین‌شات واقعی هیرو در دسکتاپ/موبایل و تست چشمی در مرورگرهای واقعی**: به همان دلیل انجام نشده. جایگزین انجام‌شده: رندر SSR کامل (jsdom) و ممیزی برنامه‌ای ساختار، تصاویر، فرم‌ها، لینک‌ها و axe.
- **بررسی رنگ/کنتراست با axe**: قواعد `color-contrast` و `target-size` در jsdom قابل ارزیابی نیستند. کنتراست متن‌ها دستی محاسبه و سقف‌ها بالا برده شده، اما تأیید نهایی نیاز به مرورگر دارد.

## ۹) استقرار

### انتشار خودکار روی GitHub Pages

مخزن شامل ورک‌فلوی `.github/workflows/pages.yml` است: با هر push روی `main`، وابستگی‌ها نصب، دارایی‌ها ساخته، دروازهٔ کیفیت اجرا و خروجی با `VITE_BASE=/taxino/` و `PUBLIC_SITE_URL=https://rahmaniho.github.io/taxino` ساخته و روی Pages منتشر می‌شود.

- حالت Pages باید روی **GitHub Actions** باشد (Settings → Pages → Source: GitHub Actions).
- نشانی انتشار: <https://rahmaniho.github.io/taxino/>
- **فرم روی این نسخه:** میزبان استاتیک است و `/api/consult` وجود ندارد؛ بنابراین فرم پس از اعتبارسنجی، پیام را آماده و با دکمهٔ «ارسال با ایمیل» به `info@taxino.ir` تحویل می‌دهد (به‌همراه دکمهٔ تماس). هیچ پیام موفقیت جعلی نمایش داده نمی‌شود. برای فعال‌کردن ارسال سروری، `VITE_CONSULT_ENDPOINT` را به یک تابع فعال (Vercel/Node) تنظیم کنید.
- نسخهٔ خودکار از دید موتور جست‌وجو، دامنهٔ `rahmaniho.github.io/taxino` را اعلام می‌کند (canonical/OG/sitemap بازنویسی می‌شوند) تا داده‌ساختاریافته با دامنهٔ واقعیِ محل سرو هم‌خوان باشد.

**الف) Vercel (توصیه‌شده):** پروژه را به Vercel وصل کنید. `dist` به‌صورت استاتیک سرو می‌شود و `api/consult.mjs` به‌طور خودکار به یک Function تبدیل می‌شود. متغیر `LEAD_WEBHOOK_URL` را در Environment Variables تنظیم کنید (دیسک Vercel پایدار نیست، پس برای تولید وبهوک یا دیتابیس لازم است).

**ب) سرور Node (VPS/cPanel با Node):**

```bash
npm ci && npm run assets && npm run build
LEAD_DIR=/var/lib/taxino/leads PORT=4173 npm start
```

سپس Nginx/Apache را به `127.0.0.1:4173` ری‌ورس‌پروکسی کنید و `var/` را از دسترس وب خارج نگه دارید.

**ج) میزبانی استاتیک خالص:** فایل‌های `dist/` را آپلود کنید؛ در این حالت فرم نیاز به تابع/سرویس جدا دارد و در غیر این صورت باید با دکمهٔ تماس جایگزین شود.
